## Reflection 1: How did AI help me with this assignment?

AI was useful mainly as a writing and organization assistant.

At the beginning, I understood the basic idea of a README, but I was not completely sure how to organize all the information in a professional way. ChatGPT helped me break the README into clear sections such as Overview, Project Files, Data, Installation, Example Code, Validation, and AI Assistance Disclosure.

It was also helpful when I was preparing the R Markdown file. It suggested a clear order for Purpose, Inputs, Main Tasks, Outputs, and Validation. That made the document easier to follow.

The biggest benefit for me was speed. Instead of spending a long time deciding how every section should be arranged, I could start with a draft and then review it myself. I still had to decide what was relevant to my project and remove anything that did not fit.

I also found that asking more specific follow-up prompts produced better results than asking one broad question.

## Reflection 2: What were the limitations of AI, and how did I verify the output?

The main limitation is that AI can produce something that looks correct even when it does not fully match the assignment or the actual project.

Because of that, I did not treat the AI response as automatically correct. I compared the content with the assignment instructions and checked whether every section was actually relevant to my store sales project.

I also made sure that AI did not provide final calculated results. The assignment requires me to perform calculations directly. For that reason, the documentation shows the R commands for `summary()`, `mean()`, `cor()`, and `plot()`, but it does not invent numerical answers.

For the Markdown, I checked the structure manually. I looked at heading levels, bullet lists, code fences, filenames, and spacing. The final README should also be checked using GitHub preview.

For the R Markdown file, the final check is to open it in RStudio or Posit Cloud and preview or knit it. This is important because a document may look correct as plain text but still have a formatting problem when rendered.

This part of the assignment reminded me that AI can help with a draft, but I still have to verify the work myself.

## Reflection 3: What did I learn from this documentation process?

I learned that good data analysis is not only about writing code.

Another person should be able to understand what the project is about, what data is being used, what each script does, what inputs are required, what outputs are expected, how to run the work, and how the work was checked.

Before this assignment, I could easily have written the R code and stopped there. Now I understand why README files and R Markdown documents are useful. They make a project easier to understand, easier to review, and easier to continue later.

I also learned that simple documentation can still be professional. It does not need difficult language. Clear headings, short explanations, correct code blocks, and a logical order make a big difference.

Finally, I learned that using AI responsibly means being transparent about where it helped, keeping a record of the prompts, checking the output myself, and taking responsibility for the final work.
